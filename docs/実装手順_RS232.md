# 実装手順書：RS-232C加工サイクル可視化ツール（八尾 / YO-003）

## 0. この手順書について

`html/ampere/realtime.html`（電流可視化・リアルタイム版）と同じ「nginxで収集ディレクトリをread-only配信 → ブラウザが差分ポーリング」方式を踏襲し、八尾拠点のRS-232CイベントJSONLを可視化する単一HTMLツールを新規に追加する。

- 実装担当: Sonnet 5
- 既存の `html/ampere/realtime.html` は一切変更しない。新版は `html/rs232/yao/` 配下に別ファイルとして追加する。
- ポーリング機構・Range差分取得・日時パース・CSS/パネル構造の下流ロジックは ampere 版を移植する。共有モジュール化はしない（本リポジトリは単一ファイル完結が方針）。

## 1. 新規作成したディレクトリ・ファイル

```
html/rs232/yao/
├── realtime.html      （新規：単一ファイル完結、ビルド無し）
└── data/
    └── .gitkeep        （新規：nginxのマウント先。空でよい）
```

加えて、既存3ファイルを変更:
- `nginx/default.conf` — location 2ブロック追加
- `docker-compose.yml` — ボリューム1行追加
- `html/index.html` — リンク1行追加

## 2. nginx設定（追加分）

`nginx/default.conf` の `server {}` 内、既存の `/ampere/data/` ブロックの後ろに追加:

```nginx
location = /rs232/yao/realtime/ {
    try_files /rs232/yao/realtime.html =404;
}

location /rs232/yao/data/ {
    autoindex on;
    autoindex_format json;
    add_header Cache-Control "no-cache";
    expires -1;
}
```

`/rs232/yao/data/` へのGETがディレクトリ一覧JSONを返す。`autoindex_format json` はnginx 1.7.9+。`nginx:1.27-alpine`で利用可。

## 3. docker-compose.yml（追加分）

`services.web.volumes` に1行追加:

```yaml
- /opt/machine-tool-info-yao:/usr/share/nginx/html/rs232/yao/data:ro
```

収集サーバー（MQTT→JSONL）の書き込み先をread-onlyでマウントする。

## 4. フロント（realtime.html）の設計

### 4.1 ampere版から移植したもの

- `fetchListing()` — autoindex JSON取得
- `ingestChunk()` — HTTP Rangeによる差分取得。バイト単位でのオフセット前進（UTF-8マルチバイト対策）
- `poll()` / `scheduleNext()` — 再入ガード付きポーリング
- `selectFilesInWindow()` — ファイル名から時間ウィンドウを絞る
- `parseReceivedTime()` / `parseDateTime()` — 日時パース
- `toLocalInputValue()` / `fromLocalInputValue()` — ローカル時刻変換（`toISOString()`は使わない）
- `escapeHtml()`
- CSS変数・パネル構造・`.hidden`トグルのデザイントークン一式

### 4.2 新規実装したもの

- `parsePayload(raw)` — payloadのパース。失敗しても復元は試みず `null` を返す。オブジェクトはそのまま、先頭が `{` でない文字列はそのまま、先頭が `{` ならJSON.parseを1回だけ試す。
- `parseTopic(topic)` — `{ machine, kind }` に分解。`yao/<機械ID>/RS232` → `data`、`.../RS232/status` → `status`、`.../RS232/error` → `error`、`yao/<機械ID>/status`（変則形）→ `status`。一致しなければ `null`（対象外カウント）。
- `parseEvent(value)` — `value.trim()` した上で `/^EVT\s+(\S+)(?:\s+ID(\d+))?/` から `{ verb, id }`。
- 機械IDごとの状態バケット `machines[machineId]`（`cycles` / `openById` / `incompleteCycles` / `endUnknownCount` / `matchangeOpenById` / `matchangeIntervals` / `deviceDrifts` / `statusEvents` / `errorEvents` / `eventLog` / `counts`）。
- ID対応付けによるサイクル抽出（`processDataRow`）。`openById` は機械バケット内に持ち、機械をまたいで参照しない。CYCLE抽出はYO-003のみに限定（`CYCLE_CAPABLE_MACHINES`定数）。
- 分位数（P10/中央値/P90）— ソート済み配列からの線形補間（`quantile()`）。
- 機器時刻のパースとズレ算出（`processDataRow` 内、`payload.timestamp` が読める行すべてで記録。CYCLE語彙対応の有無とは独立）。
- Plotly 4系統のグラフ（推移散布図・ガント・ヒストグラム/時間帯別稼働率・通信品質）を `Plotly.react()` で再描画。

### 4.3 ampere版と異なる設計判断

- **表示範囲の共有方式を簡略化した。** ampere版はデータ量が大きい（15万点上限のダウンサンプリング）ため、ユーザーがグラフをズームした際に `Plotly.relayout()` のみで済ませる最適化をしている。本ツールは対象データが数百〜数千行オーダーで小さいため、範囲変更のたびに `renderAllPanels()` で全パネルを `Plotly.react()` により再描画する方式にした。複数チャート間の表示範囲同期（`plotly_relayout` イベントを全チャートにバインドし合う）を単純な構造で実現するための判断。
- **「表示期間」と「加工時間フィルタ」の適用範囲を役割分担させた。** 推移グラフ・ガントは常に全件（閾値フィルタのみ適用、時間範囲は視覚クロップのみ）を描画し、統計サマリ・ヒストグラム・時間帯別稼働率は「表示期間 × 閾値フィルタ」の両方を反映する。ampere版の統計期間選択（F3b、`renderStats(startMs, endMs)`）と同じ考え方を踏襲した。
- **「イベントログ」パネルを新設した。** 要件定義FR-3の「他機械選択時も通信品質パネルとイベントログは通常どおり描画する」という記述に対応するため、機械種別を問わず直近100件の生イベント（data/status/error）を表示するテーブルを追加した。YO-003以外の機械（今回はサイクル抽出未対応）でも、生データの動きを確認できるようにするための追加パネル。

## 5. 検証方法

1. `docker-compose.yml` のマウント行を一時的に `- C:/dev/yao-rs232:/usr/share/nginx/html/rs232/yao/data:ro` に差し替えて `docker compose up -d`（`npx serve` ではnginxのautoindex JSONが返らないためDocker必須）
2. `http://localhost:8081/rs232/yao/realtime/` を開き、Browser MCPツールでコンソールエラー0件・Rangeリクエスト（206 Partial Content）・各パネルの描画を確認
3. サンプル9ファイル・412行での回帰チェック値（YO-003完了サイクル111件/開始のみ6件/開始不明0件、加工時間中央値0.37秒/最小0.27秒/最大337.05秒、error 49件かつ解析不能49件、機械セレクタYO-003(303)/YO-001(107)/NN-20U5-01(2)など）と突合
4. 検証後、`docker-compose.yml` のマウント行を本番の `/opt/machine-tool-info-yao` に戻す
