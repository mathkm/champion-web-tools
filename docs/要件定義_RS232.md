# RS-232C加工サイクル可視化ツール 要件定義書（八尾 / YO-003）

作成日: 2026-07-28

## 1. 背景・目的

八尾拠点の工作機械は RS-232C 経由でイベント文字列（`EVT CYCLESTART ID…` 等）を吐き、MQTT収集サーバーがそれを収集サーバー上の `/opt/machine-tool-info-yao/` に JSONL で追記している。現状これを見る手段が無く、生の JSONL を目視するしかない。

`html/ampere/realtime.html`（電流値のリアルタイム可視化）と同じ「nginxで収集ディレクトリを read-only 配信 → ブラウザが差分ポーリング」方式で、**ワークあたりの加工時間（CYCLESTART→CYCLEEND）** を主軸に、稼働状況・通信品質まで現場で即座に確認できる単一HTMLツールを追加する。

想定利用者は現場・生産技術。目的は「1個あたり何秒かかっているか」「機械が止まっている時間はどこか」「そもそも通信は健全か」を判断すること。

## 2. データ仕様（サンプル9ファイル・412行の実測に基づく）

データソース: `C:\dev\yao-rs232\*.jsonl`（本番は `/opt/machine-tool-info-yao/`）。
ファイル名は ampere と同じ `YYYYMMDD_HHMMSS_mmm.jsonl` 形式。1行1レコードのJSONL。

### 2.1 レコード共通構造

```json
{"ingest_t": "2026-07-28T15:02:02.942+09:00", "topic": "yao/YO-003/RS232", "payload": "<文字列 or JSON文字列>"}
```

`ingest_t` はISO 8601（オフセット付き）。**時間軸は必ず `ingest_t` を使う**（2.4節参照）。

### 2.2 topic 3種（実測の内訳）

| topic | 件数 | payload |
|---|---|---|
| `yao/<機械ID>/RS232` | 329 | JSON文字列 `{mac, ip, timestamp, sensor_type:"2", sensor_no:1, value}` |
| `yao/<機械ID>/RS232/status` | 32 | 裸の文字列 `"online"` / `"offline"` |
| `yao/<機械ID>/RS232/error` | 49 | JSON文字列 `{machine, type:"noise", sample, count, timestamp, is_ntp_synced}` |

機械IDはtopicからのみ得られる（payloadに無い）。実測: `YO-003`(303件) / `YO-001`(107件) / `NN-20U5-01`(2件、`yao/NN-20U5-01/status` と `/RS232` セグメントを持たない変則形)。

### 2.3 `value` のイベント語彙（実測・機械別に異なる）

**YO-003（本ツールの対象）** — 相関ID付き:
- `EVT CYCLESTART ID<n>` … 115件
- `EVT CYCLEEND ID<n>` … 109件
- `EVT MATCHANGESTART ID<n>` … 1件（材料交換）
- 末尾に空白が付く個体あり（`EVT CYCLESTART ID4021646 `）→ 必ずtrim

**YO-001（今回はサイクル抽出の対象外）** — 相関IDなし、順次対応付けが必要:
`EVT CYCLE_START P<prog>` / `EVT CYCLE_END P<prog> N<count>` / `EVT SETUP_START` / `EVT SETUP_END` / `EVT ALARM P<n>`

### 2.4 実装上の落とし穴（すべて実測で確認済み）

1. **error payloadは49/49すべてstrict `JSON.parse` に失敗する。** `sample` フィールドに生の制御文字（U+0014, U+0012等）がエスケープされずに埋め込まれている。外側のJSONL行のパースは通るが、内側のpayload文字列をparseすると必ず `Invalid control character` になる。復元は試みず、パース失敗は「解析不能」として件数のみ表示する。`topic` と `ingest_t` は外側の行から常に取れるため、error の発生件数・時間推移は失敗行でも集計できる。
2. **payloadがJSONとは限らない。** `/status` は裸の `online` / `offline` 文字列。`JSON.parse` する前に先頭が `{` かどうかで判定する。
3. **payload内の `timestamp`（機器時刻）は信用できないが、参考値として表示する。** YO-001は `1970-01-01T09:22:16` = NTP未同期。YO-003は `ingest_t` より常時約+5.7秒ずれている。時間軸・加工時間の計算には `ingest_t` のみを使い、機器時刻は画面に併記する（ズレ = ingest_t − 機器時刻）。
4. **RS-232のノイズによる値の破損。** `EVT CYCLE_END P5013 N 125`（数値内に空白混入）のような行が実在する。正規表現は厳格にし、マッチしない行は「解析不能」としてカウント表示する。
5. **対応の取れないイベントが実在する。** サンプルではYO-003にSTARTのみ6件。
6. **サンプルデータの数値そのものは意味を持たない。** テストデータと本番データが混在しており、加工時間の分布（中央値0.37秒に対し上位10%が約337秒と二極化）は機械の実態を表していない。この分布に合わせたチューニングは行わない。統計量は中央値・分位数（P10/中央値/P90）を主表示にする。
7. **statusが高頻度でoffline/onlineを往復する。** 20ms差での往復が多数あり、取りこぼしや接続不良の兆候として可視化する価値がある。

## 3. 機能要件

### FR-1 データ取得（ampere/realtime.htmlと同一方式）
- nginxの `autoindex_format json` でディレクトリ一覧を取得
- ファイルごとにバイトオフセットを保持しHTTP Rangeで差分のみ取得。行途中で切れた末尾は次回ポーリングに持ち越す
- ポーリング間隔はUIで5/10/30/60秒から選択（既定10秒）
- 初期読込ウィンドウは直近7日。開始日時入力で過去方向にのみ拡張（backfill）

### FR-2 機械IDによるデータ分離
topicの `yao/<機械ID>/RS232…` の `<機械ID>` が異なるものは、すべて別データとして完全に分離して保持する。機械IDはtopicからしか得られないため、`parseTopic()` で抽出した機械IDを全状態のキーにする。サイクル対応付けのIDマップ（`openById`）は必ず機械ごとに分ける。機械IDはデータから動的に発見し、ハードコードした一覧は持たない。UIに機械セレクタを置き、行数付きで一覧表示する。全パネルは選択中の1機械のみを描画する。

### FR-3 サイクル抽出（対象: YO-003のCYCLE系のみ）
選択中の機械がYO-003の場合のみサイクル抽出を行う。他機械を選択した場合はサイクル系パネル（推移・ガント・統計）に「この機械のイベント形式は未対応です」と表示し、通信品質パネルとイベントログは通常どおり描画する。`value` をtrimし `/^EVT\s+(\S+)(?:\s+ID(\d+))?/` で動詞とIDを抽出。`CYCLESTART ID<n>` と `CYCLEEND ID<n>` をIDで対応付け、加工時間=END.ingest_t−START.ingest_t。START のみ（END未着）は進行中/未完了、ENDのみは開始不明、同一IDの二重STARTは直前を未完了で確定して新規開始。MATCHANGESTART/ENDもIDで対応付けて区間化するが、ENDが来ないSTARTは無視する。

### FR-4 閾値フィルタ
「加工時間の下限/上限[秒]」入力欄。既定は空＝全件表示。フィルタは統計・ヒストグラム・推移グラフに適用。除外件数を常時表示。自動外れ値除去は行わない。

### FR-5 可視化（4パネル）
1. サイクルタイム推移（scattergl散布図、中央値の水平線を重畳）
2. 稼働タイムライン（ガント。加工中・材料交換・offline区間を別色で表示）
3. 統計サマリ＋分布ヒストグラム（完了数/中央値/平均/最小/最大/P10/P90/標準偏差、未完了・開始不明・解析不能件数、時間帯別稼働率）
4. 通信品質パネル（status のonline/offlineを階段状チャート、error(noise)の発生を時間バケット別棒グラフ。パース失敗行も件数に含める）

### FR-6 表示制御
「最新に追従」チェックボックス（既定ON）。ユーザーがズーム/パンしたら自動でOFF。全パネルでX軸の表示範囲を共有し、開始/終了日時入力から手動指定可能。取得ファイル数・採用行数・対象外行数・解析不能行数・最終更新時刻を常時表示。

### FR-7 機器時刻の併記（参考値）
サイクル一覧テーブル（直近100件）に開始/終了それぞれのingest_tと機器時刻、加工時間、ズレを表示。統計サマリにも機器時刻ズレ（中央値/最小/最大）を追加。

## 5. 技術方針

Plotly 2.35.2（CDN・ampereと同じピン留め）。PapaParseは不要（JSONLのみ）。バニラES2017+、IIFE + `"use strict"`、フレームワーク・ビルド無し。UI文言とコメントは日本語。`new Date(ローカル形式文字列)` に頼らず、`toISOString()` も表示に使わない（既存の `parseDateTime`/`toLocalInputValue`/`fromLocalInputValue` の方式を踏襲）。

## 6. スコープ外（今回やらないこと）

- YO-001 / NN-20U5-01の「サイクル抽出」（`CYCLE_START P<prog>` の順次対応付け、SETUP/ALARMの区間化）
- error payloadの制御文字を復元するパーサ
- ampereツールとの共通ライブラリ化（単一ファイル方針を維持）
- CSV入力対応（JSONLのみ）
- データの書き込み・編集（配信はread-only）
- CSV/画像エクスポート（Plotly標準のダウンロードボタンで代替）
